# Algorithmの開発

対象はリポジトリ直下の `PointCloudApp/Algorithm/`（このSkillからは `../../../PointCloudApp/Algorithm/`）。本文中のコードパスは、リンク先を除きこの対象フォルダを基準にする。

共通の構成・ビルド手順は [モジュールのSkill](../pointcloudapp-development/SKILL.md) を参照する。ここでは計算処理と形状データの関係を扱う。

## 調査の入口

- 空間探索は`KDTree`、`KDTreeNanoFlann`、`BVH`、三角形分割は`DelaunayGenerator`、断面は`CrossSectionLine`と`CrossSectionFill`を入口にする。
- HalfEdgeの構造、入出力、操作、表示は`HalfEdge/`にまとまっている。ノードを含むので、すべてが独立したCPU計算とは限らない。
- Voxel関連は`Voxel`、`Voxelizer`、`SignedDistanceField`を確認し、CPU計算とGPU処理の範囲を実装から判断する。
- [IAlgorithm.h](../../../PointCloudApp/Algorithm/IAlgorithm.h) は`GetType`、`Execute`、`ShowUI`を持つ。既存機能がこの経路を使う場合は呼び出し元と種類の識別も確認する。すべての計算クラスへ継承を強制しない。

## 実装の進め方

1. 呼び出し元から、入力の所有者、次元、座標系、単位、要素数と出力の利用先を確認する。入力を書き換える処理か、別の結果を返す処理かを区別する。
2. 添字の範囲、境界の表現、重複点や退化形状の扱いを対象の実装で確認する。近傍探索では半径と距離の二乗の扱いを呼び出し先まで照合する。
3. 既存のデータ構造と処理を利用して実装する。描画やUIと結び付いた処理では、結果がどのノードへ渡るか、変更後に再計算やGPU更新が必要かを追う。
4. アルゴリズムの選択が精度、計算量、入力条件を大きく変える場合だけ、その違いを説明して選択を確認する。

## 検証

変更に対応する小さな入力を使う。近傍探索なら既知の点配置、三角形分割なら点数と退化条件、HalfEdgeなら辺の相互参照と面ループ、Voxelなら範囲と格子境界を確認する。空入力や境界条件は、その処理が受け付ける契約に沿って確認する。

計算結果の要素数、添字、有限性と期待値を先に確認し、表示だけで正しさを判断しない。ファイル形式を変更する場合はローダーと保存側を併せて確認する。大きなデータでの性能測定は必要になった段階で行い、入力規模と計測範囲を記録する。
