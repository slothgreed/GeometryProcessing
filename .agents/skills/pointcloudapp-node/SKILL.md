# Nodeの開発

対象はリポジトリ直下の `PointCloudApp/Node/`（このSkillからは `../../../PointCloudApp/Node/`）。本文中のコードパスは、リンク先を除きこの対象フォルダを基準にする。

共通の構成・ビルド手順は [モジュールのSkill](../pointcloudapp-development/SKILL.md) を参照する。ここではデータをシーンに組み込み、表示と操作へ接続する。

## 調査の入口

[RenderNode.h](../../../PointCloudApp/Node/RenderNode.h) と [RenderNode.cpp](../../../PointCloudApp/Node/RenderNode.cpp) が共通の入口。汎用形状は`PrimitiveNode`、点群は`PointCloud/`、形式別の機能は`GLTF/`、`STEP/`などを参照する。共通ローダーは`Loader/`にあるが、すべての形式の読み込みがそこに集約されているわけではない。HalfEdgeのノードは`../Algorithm/HalfEdge/`にある。

## ノードの振る舞い

- 派生ノードは`DrawNode`、`UpdateData`、`ShowUI`、`PickNode`など、対象機能の既存拡張点に合わせて実装する。
- `Draw`と`Update`は子ノードをたどる。UI表示や選択結果の収集は同じ再帰の形ではないため、深い階層にも届くと仮定せず、それぞれの実装を確認する。
- 描画への参加は`GetRenderPassMask`と`DrawContext`のパスで決まる。通常描画だけでなく、必要な深度パスやピッキングとの整合性も確認する。
- 子ノードは名前をキーに保持される。同名ノードの追加が既存ノードを置き換えることを踏まえて、作成側の命名を確認する。
- 変換はモデル行列と法線行列に関わる。親子関係だけで親の変換が自動合成されると仮定しない。角度のAPIはラジアンを扱う経路と度数変換をする経路を区別する。

## 機能の組み込み

データの読み込み・生成、ノード作成、シーンへの追加、更新、描画の順に接続を追う。形状変更ではGPUへの反映と境界ボックス・カメラフィットへの影響も確認する。

対象固有の操作はノード側のUIを入口にする。アプリ全体の操作やシーン生成は`../App/PointCloudApp.cpp`を確認する。ピッキングではIDの割り当て、描画、結果収集、選択対象への反映を通して追う。

## 検証

代表的な小さなデータで、表示、変換、更新、選択、UI操作のうち変更した経路を確認する。ノードを追加・削除する変更では名前の衝突とリソースの寿命も確認する。ローダーの成功と画面への組み込み成功は別々に確かめる。
