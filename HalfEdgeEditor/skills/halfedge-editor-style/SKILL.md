# HalfEdgeEditor コード規約

エディタが成長してもソースコードを読み進めやすい状態に保つ。
整形だけを依頼された場合は、既存の動作を変更しないこと。

## 適用範囲

- `HalfEdgeEditor`以下の手書きのTypeScript、TSX、JavaScript、JSXへ適用する。
- `node_modules`、`dist`、`.next`、`.vinext`、`.vs`は編集しない。
- 親リポジトリにあるC++プロジェクトへ、この整形規則を適用しない。

## 書式

- インデントには半角スペース4個を使用し、タブ文字は挿入しない。
- 文は1行に1つとし、セミコロンで文が終わったら改行する。
- オブジェクトの生成、設定、シーンへの登録、イベント設定、後始末など、論理的なまとまりの間に空行を入れる。
- インスタンスの生成と、そのインスタンスに対する直後の設定や登録は一つのまとまりとして扱い、間に空行を入れない。
- 短く読みやすい関数呼び出しは1行のままでよい。
- 関数やコンストラクタへ値だけの位置引数を渡す場合は、引数の個数にかかわらず、読みやすい範囲で呼び出し全体を1行に記述する。
- 名前付きの設定を表すオブジェクトリテラルを引数へ渡す場合は、開始波括弧の直後で改行し、プロパティごとに行を分ける。
- 密集したオブジェクトリテラルは展開し、それぞれのプロパティを読みやすくする。TypeScriptで許される場合、複数行のオブジェクト、配列、import、JSXのpropsには末尾カンマを付ける。
- 演算子の前後、カンマの後、TypeScriptのオブジェクト型の波括弧内には空白を入れる。
- 複数の処理を含むコールバックや条件分岐では波括弧を使用する。1行のコールバックへ複数の処理を隠さない。
- JSXは視覚的に階層を追える形で記述する。セクション全体を1行へ詰め込まず、入れ子の要素や独立したpropsを別の行へ配置する。

## コードのまとめ方

- Reactのref、state、effect、コールバック、描画用ヘルパーを読みやすい単位にまとめ、空行で区切る。
- Three.jsの初期化では、geometry、material、mesh、補助表示、照明、controls、表示範囲調整、リサイズと描画ループ、後始末を別々のまとまりにする。
- 行を短くするためだけに名前を省略せず、役割が分かるローカル変数名を使用する。
- 整形だけを目的に抽象化を追加しない。責務や再利用性が明確になる場合に限って処理を抽出する。

## 検証

- TypeScriptまたはTSXを変更した後は、既存のlintコマンドを実行する。
- 実行時のソースへ影響する変更後は、既存のproduction buildを実行する。
- ブラウザ上の操作を目視確認していない場合は、その旨を報告する。
